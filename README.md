# Friday - a clean newsletter emailer

Clean up web newsletters with the [Readbility algorithm][readability] and
[ClearURLs][clearurls]' tracker cleaning ruleset and email them to yourself. On
Friday. If you want.

Born out of frustration with daily email newsletters that I don't _want_ daily,
but have no control over their actual frequency.

Outbound links that go through a click-tracking proxy are on the to-do list, so
that you could actually _see_ what you're clicking on again, like TBL intended,
and forward such emails without compromising your personal contacts through
newsletter share IDs.

Requires **Node.js ≥ 14**, because some dependencies use null-coalescing
operators. Tested with Node.js 22.

## Initial setup

```bash
mkdir -p ~/.config/friday
cp sample-config.json ~/.config/friday/config.json
```

Now, edit `config.json` in your favorite editor to customize it and/or add SMTP
authentication credentials.

> [!IMPORTANT]
> Protect this file with `chmod 600 ~/.config/friday/config.json` if it will
> contain credentials, and if you can, use an application specific password
> scoped as narrowly as possible (_e.g._, just for SMTP).

If a `~/.config/friday/style.css` is found, that will be used, with a fallback
to `style.css` in the current working directory. You can also specify a URL to
a CSS file, _e.g._ [this one][] for [Sakura][], which will be downloaded and
cached locally.

See the "[Automation using cron](#automation-using-cron)" section if you're
interested in non-interactive use, like on a home system or shared host.

## Usage

Run the script by passing a URL; for example:

```bash
    node friday.js https://static.nytimes.com/email-content/NE_sample.html
```

Or, if `node` is in your [path][], this will work, too:

```bash
./friday.js https://static.nytimes.com/email-content/NE_sample.html
```

Alternatively, you can specify a list of URLs to process using in the `"urls"`
array of your `config.json`. For newsletters that don't have a stable URL, you
can provide a CSS selector and optional attribute (defaulting to `href` for
anchors or `src` for anything else) to extract the _actual_ URL.

For example:

```json
{
  "urls": [
    "https://static.nytimes.com/email-content/NE_sample.html",
    {
      "url": "https://changelog.com/news",
      "selector": "#newsletter_iframe",
      "attribute": "src"
    }
  ],
  "and-so-on": "…"
}
```

### Flags

* `-b`, `--browse` — opens the parsed article in your default browser
* `-w`, `--wait` — used with `--browse`, keeps the local server running until a
  key is pressed; useful for viewing source or refreshing
* `-s`, `--send-email`, `--send`, `--email` — sends the parsed article via email;
  requires `"smtp"` key in `config.json`
* `-e`, `--embed-images`, `--embed` — downloads and embeds images directly into
   the HTML as `data:` URIs
* `-c`, `--clean-urls` — removes tracking parameters from URLs using ClearURLs
  rules
* `-v`, `--verbose` — enables verbose logging (e.g., show cleaned URLs)

### Automation using cron

You can automate Friday to run on a schedule using `cron`. For example, to run
the script every Friday at 8:00 AM and process the URLs defined in your
`config.json`:

```cron
0 8 * * 5 /usr/local/bin/node /path/to/friday.js --send-email >> ~/.cache/friday/friday.log 2>&1
```

> [!NOTE]
> Make sure to provide the **absolute paths** to both the `node` executable and
> `friday.js` in your crontab, since the default cron environment has a
> restricted `$PATH`.

#### Log rotation

On Linux systems, use use the standard `logrotate` utility. First, copy
[the sample configuration](sample-logrotate.conf) to your `~/.config/friday`
directory:

```bash
cp sample-logrotate.conf ~/.config/friday/logrotate.conf
```

…and edit it to replace `/home/YOUR_USERNAME` with your actual home directory.

Add a cron job to run `logrotate` with a local state file, for example, an hour
after your script runs:

```cron
0 9 * * 5 /usr/sbin/logrotate -s ~/.cache/friday/logrotate.state ~/.config/friday/logrotate.conf
```

If you don't have `logrotate` installed, you can use a simple cron job with
`tail` instead to trim the log file to, for example, 1000 lines after each run:

```cron
0 9 * * 5 tail -n 1000 ~/.cache/friday/friday.log > ~/.cache/friday/friday.tmp && mv ~/.cache/friday/friday.tmp ~/.cache/friday/friday.log
```

## Security

The HTML newsletters generated by Friday are prevented from running JavaScript
in two ways:

1. `DOMPurify` strips out all `<script>` tags, `javascript:` URIs, and inline
   event handlers (like `onclick="..."`).
2. A strict `Content-Security-Policy` meta tag is injected into the `<head>` of
   the generated HTML with `default-src 'none'`. Because there is no
   `script-src` defined, the browser will strictly refuse to execute any
   JavaScript, even if a script tag somehow bypassed the sanitizer.
